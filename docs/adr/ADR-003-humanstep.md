# ADR-003: humanStep / humanStepBack（人間にやさしいステップ実行）

- **決定日**: 2026-05-24
- **作成日**: 2026-08-10（セッションログから事後的に作成）
- **ステータス**: 承認済み

## 背景・課題

ADR-001で定義した4操作（stepIn/stepOver/stepOut/stepBack）は、AST
ノード単位の評価過程を忠実に追えるが、粒度が細かすぎる場面がある。
例えばバブルソートのような典型的なアルゴリズムをステップ実行する際、
人間が実際に注目したいのは「意味のある変化点」（代入・条件評価・
ループ更新など）であり、AST走査の内部イベント（enter/exitの区別、
部分式の評価順序）まで逐一追うのは煩雑だった。

開発者・Claude双方で、バブルソートを題材に「どの単位で止まるのが自然か」
の比較検討を行った。

## 決定

`humanStep()` / `humanStepBack()` という第5・第6のステップ操作を追加する。
内部的には`_getHumanIndices()`が、trace配列の中から「人間にとって意味の
ある変化点」に該当するインデックスだけを抽出し、そのインデックス列上を
移動する。

実装箇所:
- `debugger.js` — `_getHumanIndices()` + `humanStep()` + `humanStepBack()`
  + `getSourceLine()`
- `index.js` — `h`/`H` コマンド + `showHuman()` 表示関数

## 根拠

- 初学者向けのステップ実行では、AST走査の内部構造よりも「変数がいつ
  変わったか」「条件式がどう評価されたか」の方が学習上重要。
- 既存のtrace配列（オムニシエントデバッグ、ADR-001）に対するフィルタ
  リングとして実装できるため、新しい記録方式を追加する必要がなく、
  既存の設計資産をそのまま活用できた。

## 学び

これは4操作APIの実装が完了した**後**に、「もっと粒度を人間向けに
調整したい」という追加要求から生まれた機能である。JSVisualizer側の
ADR-005（4粒度ステップシステム）の`humanStep`相当の概念は、この
JSInterpreter側の設計がそのまま起源になっている。
