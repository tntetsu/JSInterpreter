# ADR-002: スナップショットのディープクローン化

- **決定日**: 2026-05-24
- **作成日**: 2026-08-10（セッションログから事後的に作成）
- **ステータス**: 承認済み

## 背景・課題

ADR-001のオムニシエントデバッグ方式を実装し、動かしてみたところ、
プリミティブ値（`let n = 1; n = 2;`）は正確にstepBackできる一方、
オブジェクト・配列（`let obj = {x:1}; obj.x = 2;`）は**常に最終状態が
見える**というバグが発覚した。

原因はスナップショットに保存していたのがオブジェクトへの**参照**であり、
内容のコピーではなかったこと。後から中身が変更されると、全ステップの
スナップショットに影響してしまう。

## 決定

各ステップのスナップショット作成時にディープクローンを行うよう変更する。

## 根拠

- シャロークローンでは参照が共有されたままになり、オムニシエント
  デバッグの前提（「各ステップの状態を独立して保持する」）が崩れる。
- `JSON.parse(JSON.stringify(obj))`相当のディープクローン（実装は
  構造共有等で最適化）で、オブジェクト・配列の内部変更も正確に復元できる
  ようになった（コミット`2da8bb1`「シャロークローンをディープクローンに
  変更しstepBackの精度を向上」）。

## 学び

これはADR-001の実装を**実際に動かして使ってみて初めて発覚したバグ**で
あり、教育用ツールとして致命的な精度問題だった（変数の値が正しく巻き
戻らない）。「まず実装→使ってみる→問題発見→修正」という反復が、
プロジェクト開始からわずか1日のうちに複数回起きている。
