# ADR-004: CommonJS + esbuild から ES Modules への移行

- **決定日**: 2026-05-24
- **作成日**: 2026-08-10（セッションログから事後的に作成）
- **ステータス**: 承認済み

## 背景・課題

「ここまでのコードを使ってWebページでビジュアルなデバッグ環境を作成
したい」という要求を受け、Claudeはブラウザ向けのモジュール構成案を
複数提示した。その中でesbuildによるバンドルを含む案を「推奨」として
提示していた。

開発者がこれに対して疑問を投げかけた: 「2.が好みですが，esbuildが
推奨ですか？ 今現在ではES modulesのほうがメジャーではない？」

## 決定の経緯

Claudeは指摘を受けて再評価し、率直に前言を修正した。

> ユーザーの直感は正しいです。

| | CommonJS + esbuild | ES Modules |
|-|-------------------|-----------|
| 2026年の標準 | レガシー寄り | これが標準 |
| ブラウザでの動作 | バンドル必須 | `<script type="module">`で即動く |
| Node.js | 安定 | v18+で完全サポート |
| 移行コスト | ゼロ | 小さい（このコードベースなら1時間以内） |
| 長期的な健全性 | 技術的負債 | ✓ |

> esbuildを推奨したのは「今のコードを変えなくていい」という短期的な
> 理由でした。長期的にはESMが正解です。

## 決定

CommonJSからES Modulesへ移行する（コミット`c78cffe`、5ファイル変更）。

## 学び

Claudeの最初の推奨（esbuild）は、技術的に間違ってはいないが「変更を
避けたい」という保守的なバイアスに基づいていた。**開発者が「本当に
それが最善か」と踏み込んで問い返したことで、Claude自身がバイアスを
自覚して前言を撤回した。** これは「初回は委譲、フィードバック後は具体的
指示」パターンの一種だが、実装を使ってみて気づいたのではなく、
**Claudeの提案の理由づけ自体に疑問を持って問い返した**という点で、
[agentic-coding-notes](https://github.com/tntetsu/agentic-coding-notes)の
`01-workflow.md`に記録した他の事例（ADR-001の却下等）とは異なる形の
軌道修正である。
