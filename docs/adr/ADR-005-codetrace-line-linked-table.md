# ADR-005: CodeTrace — ソースコード行に連動するアニメーショントレース表

- **決定日**: 2026-05-24
- **作成日**: 2026-08-10（セッションログから事後的に作成）
- **ステータス**: 承認済み

## 背景・課題

インタープリター本体とAPIが完成した後、「Webページでビジュアルな
デバッグ環境を作りたい」という要求から、Web UI（後の CodeTrace）の
設計に着手した。

Claudeは既存の2カラムレイアウト（Source / Debug）を踏まえ、「下部
ドロワー（VSCodeのターミナルのような、折りたたみ可能な汎用トレース表
パネル）」を含む3案を提示した。

## 決定の経緯

開発者はこの提案を却下し、要求をより具体的に指示し直した。

> 一般的なトレース表ではなく，ソースコードの横で，実行時にアニメー
> ションする（動的に変化する）トレース表．表の行数はソースコードの
> 行数と同じ．各行の実行時に各変数がどのように変化するかを，ステップ
> 実行しながら眺めることができるものを作りたい．案を考え直してください．

## 決定

トレース表を「汎用の折りたたみパネル」としてではなく、**ソースコードの
各行と1対1対応する固定行数の表**として設計する。ステップ実行するたびに
該当行の変数値がアニメーションして更新される。この機能は後に
`24cb8a1`（Web デバッガー UI追加）で実装され、`dc0eccd`で「CodeTrace」に
改名された。

## 根拠

- 「ソースコードの行 = トレース表の行」という1対1対応により、今どの行を
  実行しているかが視覚的に一目で分かる。
- 汎用的な（行数が可変の）トレース表よりも、初学者が「コードと実行結果の
  対応」を直感的に理解しやすい。

## 学び・波及効果

この「行連動のトレース表」という設計は、後のJSVisualizerの`LineTrace`
ビュー（[ADR-012](../../../JSVisualizer/docs/adr/ADR-012-linetrace-single-pane.md)
参照、単一ペイン化の議論はJSVisualizer側で独自に発生）の原型と考えられる。
JSVisualizer側のADR-012は「ソースコードパネルとトレース表の2ペイン構成
から単一ペイン化した」という別の意思決定を扱っているが、「トレース表の
各行がソースの行に対応する」という基本設計思想は、このJSInterpreterの
CodeTrace（2026-05-24）が起源である可能性が高い。この系譜の詳細な検証は
今後の課題とする。

発掘して事後的に作成した。
