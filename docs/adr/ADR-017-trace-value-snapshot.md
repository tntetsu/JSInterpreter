# ADR-017: トレースのイベントの値を、その時点の値として記録する

## ステータス

提案（2026-11-25）。修正は `fix/trace-value-clone`（master から分岐）に入れた。master へのマージと JSVisualizer の公開版の再デプロイは、時期を確認してから行う（ADR-016 と同じ手順）。共通コアの作業ブランチ（`feature/interp-core`）には同じ修正を入れた。

## コンテキスト

`Recorder.record` は、exit のイベントに、変数のスナップショット（`env`・`frameEnvs`・`globalBlockVars`）を複製して記録する。一方、そのノードを評価した値（`value`）は、複製せずに参照のまま記録していた。

そのため、配列・オブジェクトを値に持つ式（`arr` などの識別子、`[5, 3, 8, 1, 2]` などの配列リテラル、配列を返す呼び出し）では、**あとで中身が変わると、過去のイベントの値まで変わって見える**。ビューは、そのイベントの時点の値ではなく、プログラムの最後の時点の中身を表示する。

例：バブルソートの組み込みサンプル

```js
function bubbleSort(arr) { … }
bubbleSort([5, 3, 8, 1, 2]);
```

式評価のビューで、ソートの途中でも `bubbleSort([1, 2, 3, 5, 8])` と、整列し終わった配列が表示される。同じ時点の変数の欄（`arr`）は、正しく途中の並びを表示している。`arr[j + 1] = tmp` の式の展開でも、`arr` が最後の並びで表示される。

JavaVisualizer の Phase 0（JavaVisualizer の `docs/phase0-report.md` 3.2 節 a）で、Java の配列の式評価のビューを確かめたときに見つかった。JS 版でも同じことが起きている。

## 利用者に見える例

テストは `src/interpreter/debugger.test.js`（「トレースの値はその時点の値（ADR-017）」）。

```js
function bubbleSort(arr) { … }
bubbleSort([5, 3, 8, 1, 2]);
```

- 修正前：ソートの途中の式評価のビューで `bubbleSort([1, 2, 3, 5, 8])` と表示される
- 修正後：`bubbleSort([5, 3, 8, 1, 2])` と表示される（呼び出した時点の値）

```js
const arr = [1];
arr.push(2);
```

2 行目の `arr` の値は、修正後は `[1]`（`push` する前）。修正前は `[1, 2]` だった。

## 決定

exit のイベントの値を、変数のスナップショットと**同じ対応表**（`WeakMap`）で複製する。

```js
const seen = new WeakMap();
this.trace.push({
  phase: 'exit',
  …this.snapshotVars(env, seen),
  value: deepClone(traceValue, seen),   // 共通コアでは this.clone(traceValue, seen)
});
```

- 同じ対応表を使うので、同じ時点の変数と同じ配列を指す値は、スナップショットでも同じ複製を指す（参照の関係が保たれる）
- 関数・クラス（`JSFunction`・`JSClass`）は今までどおり複製しない（置換のビューが、呼び出し先の値でユーザー定義の関数かを判定する）
- 共通コア（`src/core/recorder.js`）では、言語ごとのクローン（`this.clone`）を使う。Python 版・Java 版の値（tuple の印・配列の要素の型の印など）も保たれる

## 影響の範囲

JSVisualizer の組み込みサンプル・記事の題材、examples、BhvVisualizer の授業の演習など計 194 プログラムを、修正の前後で実行して比べた（PyVisualizer の `scripts/compare-js-core.mjs` を、値とそれ以外に分けて比べるようにしたもの）。

- **値以外（変数のスナップショット・コンソールの出力・humanStep の停止点・実行の結果・エラー）は、194 本すべてで変わらない**
- 値が変わるのは 92 本（3,061 イベント）。変わったのは、識別子・配列リテラル・オブジェクトリテラル・呼び出しなど、配列やオブジェクトを値に持つ式だけ
- 修正後は、識別子の値が、同じイベントの変数のスナップショットの中身と一致する（21,778 か所すべて）。修正前は、あとで中身が変わる配列で食い違っていた
- 授業の演習では、第5回・第6回・第8回〜第13回の教材の 65 本で値が変わる（配列を使う回）。見え方が変わるビューは下の表

| ビュー | 変わるもの |
|---|---|
| 式評価 | 配列・オブジェクトを指す部分式の値（その時点の中身になる） |
| 置換 | 配列を引数に渡した呼び出しの展開（呼び出した時点の中身になる） |
| （画面の比較の結果をここに書く） | |

テストを 4 件足した。修正を外すと 3 件が失敗し、修正後は全 273 件が通る。

## 検討した選択肢

### 1. 直すか

誤った値を表示しているので直す。学生が式評価・置換のビューで、配列の途中の状態を確かめようとすると、最後の状態が見えてしまい、誤解を招く。

### 2. 反映の時期

ADR-016 と同じく、学期中でも不具合の修正として公開版に反映する。BhvVisualizer の評価計画 3.9 節に記録する。反映の日時は、授業（水曜）の時間と重ならないように決める。
