# ADR-012: 0始まりの数値リテラルと8進数エスケープをstrictモードと同じく構文エラーにする

- **決定日**: 2026-10-05
- **作成日**: 2026-10-05
- **ステータス**: 承認済み

## 背景・課題

利用側のJSVisualizerで `console.log(010)` を実行すると `10` と表示された。
レキサーが `Number('010')` で変換しており、先頭の 0 が無視されて10進数として
扱われていたためである。

JavaScript の仕様では、`010` の扱いはモードによって異なる。

| 書き方 | 非 strict モード | strict モード |
|---|---|---|
| `010`（レガシー8進数） | 8 | SyntaxError |
| `08`, `019`（0 始まりの10進数） | 8, 19 | SyntaxError |
| `"\01"`（8進数エスケープ） | U+0001 | SyntaxError |

JSInterpreter は strict モードに対応しておらず（`"use strict";` は無視される）、
どちらの規則に合わせるかを決める必要があった。

## 決定

0 始まりの数値リテラル（`010`・`08`）と文字列の8進数エスケープ（`\01`〜`\9`）は、
strict モードと同じく **構文エラー（LexError）** にする。`\0` 単独（直後が数字でない）は
両モードとも有効なので許可する。エラーメッセージには正しい書き方（`0o10`、先頭の 0 を
取り除く、`\x01`）を示す。

あわせて、Node.js と結果が異なっていた次の2点も修正した。

- 16進・8進・2進数リテラルの数値セパレーター（`0x1f_ff`）が構文エラーになっていた
- 先頭が小数点の数値（`.5`）が構文エラーになっていた

## 検討した代替案

- **非 strict モードの規則に合わせる（`010` → 8）**: 一度はこの方式で実装した。
  仕様には忠実だが、`010` が 8 になるのは学習者にとって気づきにくい誤りのもとであり、
  strict モードではこの書き方自体が禁止されている。ES モジュールや `class` 本体など、
  現在の JavaScript では strict モードで書かれることが多い。
- **strict モード全体に対応する**: `"use strict";` の検出、`this` の扱い、
  未宣言変数への代入エラーなど影響範囲が大きく、今回の不具合修正の範囲を超える。

主な利用者が JavaScript の学習者であるため、紛らわしい書き方はエラーとして気づかせる
ほうが教育上よいと判断した。

## 影響

- strict モード非対応である点を README の「ランタイムの制限」に記載した。
  数値リテラルと8進数エスケープだけは strict モードの規則で動く。
- JSVisualizer 側では、`[Lexer]` で始まるエラーを「構文エラー」として表示するよう
  エラー分類も修正した（従来は「実行エラー」に分類されていた）。
- テンプレートリテラル内のエスケープ（`readTemplateChar()`）は今回の対象外。
